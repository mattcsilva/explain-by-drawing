# Drawing an explanation

## Use space to express a relationship

Nest parts inside a boundary when they belong to the thing it represents. Label the boundary with its meaning, such as a machine, process or responsibility. An arrow can indicate order, cause or transfer. Label it with an action or with the item being carried so readers can tell which relationship you mean. Use an undirected line for an association.

Give the main path one reading direction. Give outgoing requests and returning results separate paths when that prevents a crossing. Put each label close to its arrow in the space between boxes. Keep comparable cases in the same arrangement and change only what the reader needs to compare. Check whether proximity or relative size might imply a false relationship.

Identify roles in words as well as color. Give the question and the central parts the most visual weight. Keep any condition that changes the answer visible at reading size.

The generator supplies four layouts with calculated spacing. Choose one from the lesson plan and compare your sketch with a worked example. [Components](components.md) · [Lesson plan](lesson-plan-and-review.md) · [Worked examples](worked-examples.md)

## Suggested visual settings

Start with a light background, dark text, a restrained palette and space around each connection. Adapt to the material and the reader's preferences.

- Try `#fffdf7` for the background and `#243447` for the text. Accent colors include blue `#1971c2`, green `#2b8a3e` and amber `#b46514`.
- For a hand-drawn board in Excalidraw, try a handwriting font, a stroke width around 2 and roughness around 1.
- On a board near 1080 × 760, try 34–38 for the title, 24–28 for component names and 18–23 for arrow labels. Adjust after viewing the board at the intended size.
- Reserve margins and gaps for arrowheads and labels. Split a dense board into stages while preserving legibility.
- Leave space for the application interface when framing the drawing. Inspect the export and, when available, the board in the application.

Use recognizable shapes for physical objects when their appearance helps the reader identify them. Keep every mark that you add tied to the explanation.

## Worked decision

“Will my remote test stop if my internet connection drops?”

Place the laptop and the remote development environment in separate regions. Put the running test inside the remote region. Show commands traveling out and results traveling back. Break the connection visually, then show the conditions for continued execution. The task must survive its session and the remote environment must keep running.

Compare that situation with stopping the remote environment itself. Draw the running process and the stored files as separate objects so the reader can trace what happens to each. Verify the actual product and configuration before applying the example to a deployment.

## Review the drawing

Read the board at presentation size. Can you locate the parts, follow the example and point to the condition that changes the outcome? Check arrowheads, crossings, clipping and which parts sit inside each boundary. Make sure the meaning survives when colors are hidden.

Report learning outcomes only when the user has demonstrated them. Feedback on the presentation describes the presentation. An average effect from a study can inform the design while the individual reader's understanding still requires its own evidence.
